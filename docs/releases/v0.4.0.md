# ArchMap v0.4.0

ArchMap v0.4.0 introduces the plugin-first lifecycle foundation while keeping
`@archmap/core` focused on the semantic graph, rendering, and extension APIs.

## Highlights

- Added an isolated plugin registry in Core for element types, relation types,
  validators, and plugin-provided views.
- Added the `@archmap/lifecycle` workspace package with Requirement,
  Acceptance Criterion, Decision, Risk, Test, Evidence, and typed relation
  support.
- Added lifecycle projection views for Requirements, Traceability, and Quality.
- Added deterministic graph trace APIs for lifecycle and architecture links.
- Added DSL-authored Runtime view support and runtime-oriented sample output.
- Improved Topology, Overview, Layer, and Prototype rendering readability with
  safer routing, label handling, multiline labels, contiguous swimlanes, and
  configurable layer backgrounds.
- Updated the demo to install the lifecycle plugin and expose lifecycle views
  alongside existing architecture views.

## Compatibility

- Existing v0.3.x architecture documents remain valid.
- Lifecycle sections are opt-in through `@archmap/lifecycle`; Core does not
  hard-code lifecycle vocabulary.
- Icons remain external via `@archmap/icons`.

## Verification

Release verification should pass:

- `npm run typecheck`
- `npm test`
- `npm run build`

NPM publication is intentionally left to the maintainer:

```sh
npm publish --access public
npm publish --workspace @archmap/lifecycle --access public
```
