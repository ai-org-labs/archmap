# ArchMap v0.4.1

ArchMap v0.4.1 publishes the first complete ArchMap Next topology slice while
preserving the released architecture and lifecycle authoring surfaces.

## Highlights

- Added a plugin-neutral canonical topology model for Resources, structural
  Containers, semantic Overlays, and direct Resource-to-Resource communication.
- Added native `topology:` DSL parsing while retaining legacy graph, `nodes`,
  `zones`, `boundaries`, and `edges` compatibility normalization.
- Added deterministic Container forest and ancestry validation with support for
  multiple roots and resources outside a Container.
- Added layout-independent derivation of ordered Container Crossings and Overlay
  Transitions, including exact reverse traversal for bidirectional communication.
- Added topology projection invariants: Views may filter authored topology but
  do not invent shortcut edges.
- Added provider-neutral validator registration and sample validator plugins.
- Added Topology rendering for Crossing and Overlay Transition signals.
- Refined nested Container padding, zone borders, and orthogonal subgraph frames.
- Split the GitHub Pages demo into focused Next, Playground, Examples,
  Prototype, and Lifecycle pages.
- Added an FQA compatibility review for the native and legacy DSL surfaces.

## Compatibility

- Existing v0.4.0 documents continue to parse and render.
- Legacy `zones` normalize to structural Containers and legacy `boundaries`
  normalize to semantic Overlays.
- Native `topology:` is additive. Authors can migrate incrementally instead of
  rewriting existing documents.
- Geometry does not determine Crossing or Overlay Transition semantics.

## Verification

The release gate runs:

- `npm run verify:next`
- `npm pack --dry-run`
- `npm pack --workspace @archmap/lifecycle --dry-run`
- standalone Pages asset and route checks

NPM publication remains a maintainer action:

```sh
NPM_CONFIG_CACHE=/tmp/archmap-npm-cache npm publish --access public
NPM_CONFIG_CACHE=/tmp/archmap-npm-cache npm publish --workspace @archmap/lifecycle --access public
```
